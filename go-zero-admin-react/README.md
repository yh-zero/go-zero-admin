# go-zero-admin-react

管理后台前端：React 19、TypeScript 严格模式、Vite 8、TanStack Query、zustand、axios、antd 6。登录页已按授权接入 Rive 猫咪，新增 `@rive-app/canvas` 和 `@rive-app/react-canvas`；依赖版本以 `package.json`、`pnpm-lock.yaml` 为准。

## 已接入范围

以下为已实现的页面与请求封装，具体字段和路由以 [API 契约](../ai_document/api-contract.md) 为准；已接入不代表全部异常、权限和部署场景均已验收。

| 模块 | 前端能力 |
|---|---|
| 认证 | 验证码、登录、会话恢复与令牌刷新、服务端退出、多标签页同步；猫咪默认互动、密码聚焦捂眼及登录结果反馈 |
| 用户 | 分页筛选、详情、增改删、重置密码、头像维护，以及按权限分配角色 |
| 部门 | 组织树、负责人账号、直属成员分页、增改删及当前部门切换，成员读取遵循数据范围 |
| 角色 | 筛选、详情、增改删，按页面分组的入口与操作独立授权 |
| 菜单 | 目录/页面树、名称与状态筛选、详情、增改删、操作权限抽屉、上级树选择、我的菜单和权限码 |
| 字典 | 筛选、按编码详情、增改删、字典项表单 |
| API 资源 | 筛选、删除资源登记，以及超级管理员同步接口资源 |
| 文件 | 公开/私有文件上传、筛选、访问链接、删除和引用保护 |
| 审计 | 筛选、分页和操作记录详情 |
| 个人资料 | 资料与头像维护、修改密码、查看登录设备、撤销单个设备和退出全部设备 |
| APP管理 | 用户详情、审核启停、昵称/内部备注、头像与设备、会员套餐及开通撤销、意见反馈回复 |
| 健康检查 | 通过 `/ping` 显示工作台服务连接状态 |

APP管理已有专属后台页面，与系统管理同级；AI、租户目前提供 HTTP 与 RPC 接口。实际验收范围见 API 契约及后端待办，数据库样例不作为外部服务联调通过的证据。

## 开发与检查

要求 Node `^24`、pnpm `11.28.5`，与 `package.json` 一致。依赖按锁文件安装：

```powershell
pnpm install --frozen-lockfile
pnpm dev
pnpm exec tsc -b
pnpm exec vite build
pnpm lint
# pnpm build 等价于 tsc -b && vite build
```

默认前端地址 `http://127.0.0.1:5999`，端口占用时直接报错，开发代理默认指向后端 7001。可复制 `.env.example` 到被忽略的 `.env.local`，指定另一个已启动的后端：

```dotenv
VITE_API_BASE_URL=/v1
VITE_API_PROXY_TARGET=http://127.0.0.1:7001
```

`VITE_API_BASE_URL` 控制浏览器请求前缀，默认 `/v1`；`VITE_API_PROXY_TARGET` 控制开发服务器的 `/v1` 和 `/ping` 代理。前端环境变量均会公开到客户端，不放任何密钥。

后端使用 `../go-zero-admin/docker-compose.yml` 的 `gozero-platform` 栈，标准端口为 API 7001、MySQL 3307、Redis 16379、RustFS 19000。启动与环境说明见 [开发手册](../ai_document/dev-guide.md)。

## 对接约定

所有请求经 `src/utils/request.ts`：标准 Bearer、业务错误统一提示，按契约解析响应信封并兼容旧裸对象和空响应。访问令牌到期或收到有效会话的 401 时尝试刷新，刷新失效后清理会话；登录、刷新与退出通过 Web Locks 协调多标签页，要求支持该能力的 HTTPS 或本机环境。服务端数据用 Query，写成功使相关查询失效；服务端退出配合取消请求和清理缓存，迟到的旧会话响应不能注销新账号。

权限仅采用后端返回的权限码，读取失败时不开放管理写操作；提交时再次检查当前权限，已打开弹窗也不能沿用失效权限。后端仍是实际授权边界。菜单采用本地组件白名单和安全内部路径，支持嵌套与刷新恢复；导航失败提供已接入页面入口及重试。

菜单主区只展示目录和页面，操作权限在所属页面的抽屉维护；未归属有效页面的既有操作保留独立入口。角色功能授权将页面入口和具体操作分开勾选，保留隐藏、停用和资源列表之外的既有授权 ID；保存仍提交完整授权集合。此调整沿用原接口与数据结构，不改变后端 Casbin 接口策略。

编辑表单先加载已有资料，支持部分更新的表单按契约提交已编辑字段；角色或菜单树读取失败时不能提交菜单授权。后台刷新只回填未编辑字段，保留当前草稿；切换对象或关闭重开清理旧草稿。提交期间禁用表单和取消/关闭入口，避免重复提交或请求期间切换编辑对象。各分页列表删除后若当前页超出有效范围，会重新请求有效末页，并保留筛选与每页条数。

部门编辑允许修改上级部门，前端排除自身和下级部门，后端仍负责权限、防环和子树路径维护；当前部门切换会重新加载相应数据和权限。头像上传后需保存用户或个人资料才完成绑定，也支持移除头像。服务端错误和不可用能力需在验收记录中区分，不能用静态页面或已有数据库记录替代真实接口验证。

## 测试数据（历史导入记录）

本节保留此前样例导入与验证证据，不表示本次提交重新执行了这些步骤；当前实现和最新验证边界见文末对接记录。

导入入口仅接受 `gozero-new-mysql` 容器和 `gozero_admin` 业务库。当前 compose 使用 `gozero-new-mysql-data` 数据卷；补全脚本还访问同一实例的 `gozero_platform` 控制库。运行前须完成两库既有表的初始化并备份数据，脚本不创建或迁移业务表。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File ./scripts/seed-test-data.ps1
```

入口依次执行两份 SQL：

- `seed-test-data.sql`：基础管理样例，固定 ID 分布在 `9001000–9001999`，包括 5 个部门、28 个用户、4 个角色、31 个菜单、75 个角色菜单关联、41 条 API 资源、4 个字典、32 条样例 Casbin 规则及 12 条模拟审计。
- `seed-full-test-data.sql`：新增 45 条跨模块样例，具体 ID 与边界见下表。

| 表／用途 | 数量 | 固定 ID | 覆盖内容 |
|---|---:|---|---|
| `sys_role` | 1 | `9010001` | 停用角色，不增加权限或用户关联 |
| `sys_dict` | 1 | `9010010` | 空字典项数组 |
| `app_user` | 8 | `9010101–9010108` | email/phone 两种身份，pending/active/disabled/rejected 四种状态，验证与登录时间差异 |
| `app_membership_grant` | 6 | `9010201–9010206` | 生效、过期、未来、撤销、重叠、自助授予及独立幂等标识 |
| `ai_conversation` | 4 | `9010301–9010304` | 当前管理员与其他样例用户归属、空会话 |
| `ai_message` | 12 | `9010401–9010412` | system/user/assistant/tool 四种角色，多轮文本与工具调用记录 |
| `ai_workflow` | 3 | `9010501–9010503` | 空步骤、文本统计、审批展示；全部禁用、无调度 |
| `ai_task` | 7 | `9010601–9010607` | pending/running/pending_approval/succeeded/failed/rejected 六种模拟状态 |
| `tenant_registry` | 3 | `9010701–9010703` | 两条 stopped、一条 error；明确标注纯测试且未部署 |

补全记录使用 `demo_full_` 前缀，租户 slug 使用 `demo-full-*`。邮箱使用保留的 `example.test` 域，号码使用不可投递的测试前缀；导入不会发送邮件或短信。App 样例在数据库内沿用现有管理员密码哈希，租户占位凭证由数据库随机生成，SQL 源文件和统计输出不包含凭据值。

每份 SQL 自成事务：逐条双向核对固定 ID 与自然身份，再只插入缺失记录，不覆盖既有可编辑字段。补全事务按模块立即检查行数和关联，再推进下一组；冲突或断言失败会退出并回滚当前文件。前一份已成功提交的数据不会因后一份失败被删除，可修正原因后重跑。ID 区间只是定位提示，脚本只认领逐条声明的记录，不认领区间空位。固定 ID 会推进自增序列，临时验收记录应使用独立标识并单独清理。

本轮实际验证了回滚预演、正式导入、逐模块字段与关联检查、完整幂等重跑，以及固定 ID／自然身份两种冲突拒绝。重跑前后 45 条记录的所有字段保持不变；临时 SQL 已清理，保留数据未删除。

另有 3 个既存真实 RustFS 对象及 `sys_file` 元数据：公开文本、私有 CSV、被引用文本，ID 为 `9001901–9001903`。本轮只读 HEAD 检查均为 200，大小与数据库一致。SQL 不重新上传对象、不修改旧用户头像，也不清空 Redis。

AI 消息和任务状态是展示数据，不代表本轮执行了模型或工作流。三个展示租户没有部署栈，不应对其执行启停、删除栈或管理员密码重置；导入脚本不会触发这些操作。
