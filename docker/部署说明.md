# 服务器部署

服务器只需 Docker 与 Docker Compose v2（含 BuildKit）。全部操作通过 `docker/deploy.sh` 完成，命令在后端仓库根目录执行。

## 快速开始

```sh
./docker/deploy.sh init      # 生成 docker/.env.deploy（随机密钥，权限 600）
./docker/deploy.sh check     # 校验环境文件与 Compose 配置
./docker/deploy.sh up        # 启动依赖 → 构建 → 启动全部服务
./docker/deploy.sh import    # 仅首次：向空库导入 data/db/gozero-admin.sql
```

页面 `http://127.0.0.1:8080`，用 `admin / 123456` 登录后立即改密（`DEFAULT_USER_PASSWORD` 只影响“重置密码”）。全新安装共四个后台账号，另有 `operator`（运营人员）、`viewer`（只读观察员）、`disabled`（绑定只读角色 3 的停用示例），后三者初始密码均为 `Demo@123456`；`disabled` 的 `enable=2`，不能登录。角色仍为超级管理员、运营人员和只读观察员三个。运营可读取 App 用户与会员列表，审核和维护用户状态、头像，并上传和读取本人文件；无设备撤销、会员开通或撤销、系统配置权限。只读只开放首页及 App 用户、会员列表读取，无操作按钮和写权限。

App 示例邮箱为 `member@example.test`、`vip@example.test`、`pending@example.test`、`disabled@example.test`、`rejected@example.test`、`expired@example.test`，密码均为 `Demo@123456`。member、vip、expired 为可登录的 active 状态，另外三个分别为待审核、禁用和拒绝，不能登录。三条 VIP 授予分别展示有效、过期、撤销：vip 自导入 UTC 时间起有效 30 天，expired 已过期，member 的授予已撤销；两个普通账号均无有效 VIP。示例邮箱未经过真实验证，`verified_at` 均为空。

完整演示还包括 3 部门、2 岗位、3 张实际 RustFS PNG（2 公开、1 私有）、1 条手工业务引用演示删除保护、3 条内置演示审计、1 条 AI 对话及 2 条消息和 1 条已完成任务。图片素材内置于 `storage-init` 镜像，通过条件写入仅补齐缺失对象，不覆盖已有同键文件；所有用户使用默认头像。预置 AI 历史不调用真实模型、不产生费用；有效后台与 App 会话由真实登录产生。对外提供服务前处理这些示例账号和数据，详细说明见 [数据库文档](../data/db/README.md)。

`import` 只导入空库。初始化 SQL 由历史基线、迁移、管理员初始化脚本和依次追加的 `seeds/demo.sql`、`seeds/activity.sql` 生成；RustFS 初始化流程准备演示图片对象。这两份示例 seed 只影响全新安装，不用于已有数据库升级。已存在的数据卷不会因为初始化文件更新而自动变化。

## 命令

| 命令 | 作用 |
|---|---|
| `init` | 生成 `.env.deploy`（4 个 64 位随机密钥），已存在则拒绝覆盖 |
| `check` | 必填项、占位值、密钥互异、`compose config` |
| `up` | 启动 mysql/redis/etcd，再构建并启动 rpc/ai-rpc/api/web |
| `import` | 仅向空库导入完整初始化 SQL，非空库直接拒绝 |
| `migrate-check` | 只读，列出待应用 / 已应用 / 校验和不符 |
| `upgrade` | 停写服务 → 备份 → 逐条确认执行迁移 → 启动 |
| `rollback <文件>` | 用备份覆盖业务库（需输入 `yes`） |
| `swagger` | 启动 Swagger UI |
| `status` / `logs [服务]` / `stop` | 状态、日志、停止（保留数据卷） |

## 端口

| 服务 | 地址 |
|---|---|
| 页面（Nginx 把 `/api/` 转发到 `api:7001`） | `127.0.0.1:8080` |
| API | `127.0.0.1:7001` |
| Swagger（`deploy.sh swagger`） | `127.0.0.1:8081` |

MySQL、Redis、etcd 与 RPC `6001/6002` 不发布宿主端口。对外由服务器 HTTPS 入口转发到 `8080`。Swagger 管理文档在 `:8081/`，App 文档为 `?audience=app`。

## 代理信任

注册、登录、验证码按客户端 IP 限流，注册 IP 与归属地入库展示。`APP_TRUSTED_PROXY_CIDRS` 只填**实际反向代理容器**地址（IPv4 `/32`、IPv6 `/128`，逗号分隔），留空表示忽略转发头。

```sh
docker compose --env-file docker/.env.deploy -f docker/deploy-compose.yml ps -q web
docker inspect <容器ID> --format '{{range .NetworkSettings.Networks}}{{println .IPAddress}}{{end}}'
```

结果加 `/32` 写入 `.env.deploy`，再执行 `docker compose --env-file docker/.env.deploy -f docker/deploy-compose.yml up -d --no-deps api`。**不要**填 Docker 子网、宿主/NAT 网关或 `0.0.0.0/0`，否则可伪造 `X-Forwarded-For` 绕过限流。容器重建后 IP 可能变化。

## 升级

`./docker/deploy.sh upgrade` 会依次：停 `api ai-rpc rpc`（AI RPC 也写库）→ `mysqldump` 备份到 `data/db/backups/` 并写 `.sha256` → 比对 `schema_migrations` → 对每个未应用迁移逐条询问，确认后执行并登记 `filename` / `checksum` / `applied_at` → 重新构建启动。新备份默认被 Git 忽略；包含本地账号与业务数据的备份不应公开，也不参与 fresh 初始化文件生成。

规则：

- 校验和不符 → 脚本停止，先核实实际结构，不要重跑。
- 某条迁移执行失败 → 脚本停止且不登记，核实部分执行状态后再处理。
- `checksum` = 文件按 UTF-8（去 BOM）、CRLF→LF 后的 SHA-256，64 位小写十六进制。
- 迁移按文件名顺序执行；App 两份迁移（`20261019_app_members.sql`、`20261019_app_registration_ip.sql`）不授予角色权限，需要时在停服窗口手动执行 `data/db/operator/20261019_app_member_admin_bootstrap.sql`。
- 现有库不能靠 Docker 自动升级，也不能重放全量 SQL 或单独执行 `seeds/demo.sql`、`seeds/activity.sql`；已有账号、角色及业务数据不会因 fresh seed 调整而重置。
- 数据库版本按迁移记录、校验和与实际结构核对，不能通过表数量判断。
- 备份与 `.sha256` 配套保留，并按部署方的保留策略存放到受控位置；重置或恢复前先核验目标库及备份可恢复性。

仓库随附的 `data/db/backups/` 只保留最新可公开演示库快照 `gozero-admin-demo-latest.sql` 和配套 `.sha256`。部署脚本继续在该目录生成私有业务备份，这些文件默认由 Git 忽略，不能提交。本机历史私有备份整理在 Git 忽略的 `.cache/db-backup-archive/`，仅供本机回退；生产备份应按部署方策略使用受控且可恢复的存储方案，不公开账号、令牌、业务记录和密钥。

## 配置要点

- `docker/.env.deploy` 由 `init` 生成，不入库、不进镜像；`SMTP_*`、`API_KEY_*` 留空即关闭。RustFS 管理与应用密钥分别生成，只将应用密钥注入业务 RPC。
- RustFS 1.0.3 随 Compose 启动，`storage-init` 幂等创建公私 Bucket、访问策略、下载 CORS 和应用身份。`STORAGE_EXTERNAL_ENDPOINT` 设置为浏览器实际访问的 HTTPS 文件服务地址，`STORAGE_CORS_ORIGINS` 设置为前端完整来源，多个以逗号分隔。
- 默认 S3/控制台仅绑定 `127.0.0.1:9000/9001`，通过受控反向代理开放文件接口；控制台保持管理网络访问。代理保留原始 Host、对象路径及签名查询参数。
- `rustfs_data` 和 `rustfs_logs` 持久卷与开发 Compose 分开，正常停止时保留持久卷；备份应同时覆盖数据库、对象卷及存储策略。删除卷属于有损操作，不能作为升级或检查数据库版本的步骤。升级前固定镜像版本并备份，单机卷不提供磁盘冗余。
- 服务不读 `application/*/etc/*.yaml`：`entrypoint.sh` 按 `CONFIG_SECTIONS` 从 `docker/config.yaml.template` 取段落（`api` 段或 `common` + 对应 RPC 段），一次 `envsubst` 生成 `/tmp/config.yaml`。改模板后需 `./docker/deploy.sh up` 重建镜像。
- 归属地依赖离线库 `data/ipregion/`，部署包必须携带；不向外部服务发送用户 IP。
- AI 参数在 `config.yaml.template` 的 `ai-rpc` 段（`Enabled`、`Provider`、`Model`、`BaseURL`），默认关闭；密钥只用 `API_KEY_DEEPSEEK` / `API_KEY_QWEN`，仅注入 `ai-rpc`。
- RPC 认证：两个 RPC 启用 `Auth` 与 `StrictControl`，凭据登记在 Redis `go-zero-admin:rpc:tokens` 与 `go-zero-admin:ai-rpc:tokens`。轮换时停全部 API/RPC → 删除两个哈希下对应字段 → 更新配置 → 统一启动。

## 本地开发

后端根目录 `docker compose up -d --build --wait`（根编排，新 MySQL 卷自动导入 SQL，API `7001`，Swagger `7000`），前端同级目录 `pnpm dev`（`5999`）。见 [README](../README.md#快速开始)。
