# 服务器部署（与本地开发分开）

本地开发只运行根目录 `docker-compose.yml` 的依赖服务。服务器使用 `docker/deploy-compose.yml`，包含 API、RPC、MySQL、Redis、etcd 和 Swagger，项目名为 `go-zero-admin-deploy`。部署数据卷独立于开发数据卷，不会自动使用本机开发数据。

## 1. 打包和上传

从 go-zero-admin 根目录打包：

```sh
tar --exclude=docker/.env.deploy -czf go-zero-admin.tar.gz application data/db data/api/generated docker go.mod go.sum
```

包含 Dockerfile、部署 Compose、`deploy.env.template` 和 Swagger JSON。不要上传本地密码文件、Git、IDE、日志或编译产物。上传到服务器后：

```sh
mkdir -p ~/go-zero-admin
tar -xzf /tmp/go-zero-admin.tar.gz -C ~/go-zero-admin
cd ~/go-zero-admin
```

## 2. 仅在服务器配置部署环境

服务器需安装 Docker 与 Compose。首次复制部署模板，已有配置不要覆盖：

```sh
cp docker/deploy.env.template docker/.env.deploy
chmod 600 docker/.env.deploy
openssl rand -hex 24
openssl rand -hex 32
nano docker/.env.deploy
```

填写独立的数据库强密码、JWT 密钥和默认用户密码，替换所有占位值。`SWAGGER_API_URL=http://api:7001` 用于容器内访问 API。API 和 Swagger 默认仅绑定服务器本机，可通过 HTTPS 入口或 SSH 隧道访问。MySQL、Redis、etcd 不向宿主机暴露端口。OSS 可选，未配置时无法上传图片。

## 3. 构建并启动

以下命令始终在项目根目录执行，并明确选择部署文件：

```sh
docker compose --env-file docker/.env.deploy -f docker/deploy-compose.yml config --quiet
docker compose --env-file docker/.env.deploy -f docker/deploy-compose.yml up -d --build
docker compose --env-file docker/.env.deploy -f docker/deploy-compose.yml ps
docker compose --env-file docker/.env.deploy -f docker/deploy-compose.yml logs --tail=100 api rpc
```

首次构建会下载 Go 依赖并编译 API/RPC。MySQL 空卷首次启动导入初始化 SQL，已有卷不会重复导入；修改环境中的数据库密码不会修改现有数据库密码。演示账号和权限正式使用前应替换。

```sh
curl -i http://127.0.0.1:7001/v1/sys/randomImage
```

Swagger 页面位于服务器本机 8080 端口。如果同机已有开发 API/Swagger，占用相同端口，请在部署环境配置中调整 API_PORT/SWAGGER_PORT；开发和部署项目名不同不代表宿主机端口可以重复占用。

## 4. 更新或停止

更新前备份数据库，再上传新的压缩包。不要覆盖服务器已有的 `docker/.env.deploy`：

```sh
docker compose --env-file docker/.env.deploy -f docker/deploy-compose.yml exec -T mysql sh -c 'exec mysqldump -uroot -p"$MYSQL_ROOT_PASSWORD" "$MYSQL_DATABASE"' > ~/go-zero-admin-backup.sql
tar -xzf /tmp/go-zero-admin.tar.gz -C ~/go-zero-admin
docker compose --env-file docker/.env.deploy -f docker/deploy-compose.yml up -d --build
# 停止服务，保留容器和数据
docker compose --env-file docker/.env.deploy -f docker/deploy-compose.yml stop
```

不要使用 `down -v` 清理数据库。项目没有自动增量数据库迁移，需要表结构变更时先备份并单独执行迁移。只更新生成的 Swagger JSON 时刷新网页即可，无需构建镜像。
