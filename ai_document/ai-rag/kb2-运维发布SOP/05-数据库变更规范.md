# 数据库变更规范（演示数据）

## 变更分类

- 低风险：加索引、加可空列、扩大 varchar 长度。工作日窗口内执行，DBA 复核即可。
- 中风险：新建表、删除索引、修改列默认值。须评审 + 备份 + 回滚方案。
- 高风险：删列、改列类型、删表、大表 DDL。原则上禁止直接执行，须走"建新表 + 双写 + 迁移 + 校验 + 切换"的绕行方案；大表使用在线 DDL 工具并限速。

## 执行纪律

1. 任何变更前先确认目标实例与库名，禁止凭连接别名记忆操作；变更脚本与回滚脚本成对评审。
2. 完整备份优先：变更前导出受影响表的快照或全库备份，记录导出时间与校验值；禁止用初始化脚本代替运行库备份。
3. 禁止全表无条件 UPDATE/DELETE；批量数据修复须分批、带 WHERE 边界并先 SELECT 核对行数。
4. 变更完成后 30 分钟内观察慢查询与错误日志，确认无回归后关闭变更单。

## 缓存一致性

涉及被缓存行的变更，须在提交后精确失效对应缓存键；禁止用 FLUSHALL/FLUSHDB 代替精确失效。缓存失效失败时必须在变更单中记录"库已提交、缓存未清"的状态，不得宣称已回滚。
