# 知识库前后端深度优化（2026-11-17）

## 目标与方案

用户授权同时优化前后端的速度、准确率与操作体验。沿用现有 React/antd/Query、go-zero、MySQL、Redis、Qdrant 与模型适配，不新增或升级依赖，不重置数据、不批量重建索引。开发阶段未提交；用户随后明确授权全面复查、补齐必要验证后提交并推送，接续结果见末节。

| 方案 | 收益与代价 | 本轮决定 |
|---|---|---|
| 调整提示词、增加召回或引入重排模型 | 可能改善部分问法，但增加用量与等待，且不能修复重复请求或证据截断 | 暂不采用 |
| 基于现有链路优化查询向量复用、证据窗口、队列与页面状态 | 可分别用调用数、真实片段和操作回归证明收益，保留现有归属及引用边界 | 采用 |
| 更换向量库、分块体系或页面框架 | 需要迁移和重建，影响范围远超当前可定位问题 | 暂不采用 |

此处的具体实现策略由本轮代码审计决定；不把它写作用户指定的实现细节。准确率验收分为确定性证据保留和真实模型回答效果，不能混称生产准确率。

## 重点边界

1. 缓存损坏、失败、不通或模型/owner 变化不能复用错误向量；删除资料后即使命中缓存也不能返回旧正文。
2. 某个等待者取消不影响其他有效等待者；全部取消后释放付费请求与 flight；账本仍只记录真实供应商尝试。
3. 片段必须逐字属于同一原始 chunk，不拼接不同段落、不重写 JSON，不以关键词命中冒充语义正确。
4. 前端切换身份或权限时旧结果失效；回填问题不得覆盖未知运行或隐式创建付费任务。
5. 页面状态保留不应导致隐藏面板继续轮询；只读查看/取消不能失效整个知识库。

## 实现与审查结果

六项已按下述验证范围完成。查询向量只复用成功结果，拒绝维度异常、非有限值、JSON `null` 和全零方向；冷 miss 的 flight 内二次读缓存，避免迟到 miss 重复外呼。等待者分别取消，全部离开时取消尚未完成的调用；取消不撤销已完成外呼或已提交缓存。缓存 hit 为一次 Redis GET，冷 miss 增加第二次 GET 和成功后的 SETEX；缓存读写各限 200ms，供应商计量只覆盖真实尝试。

单 reaper 每轮结束等待 5 秒，整轮上限 2 分钟；Expired 与每次向量删除分别使用继承父取消的 5 秒子截止。独立审查先发现共享 5 秒期限会跳过后续已 failed 作业的删除，已以首项超时后仍处理后续 ID 的红→绿回归修复。缓存 `null` 误解码同样先复现再修复。最终审查未发现遗留 P1/P2。

检索授权路径仍为一次 SQL，但从完整 KB 投影的五项相关统计子查询改为只校验当前 id/owner/软删。原 MySQL 状态、归属和正文复核保持，不缓存权限或召回结果。静态分析发现新增 `sync.Once` 使两个旧测试复制 ServiceContext 时复制锁；已改为显式组装新实例依赖，使实例拥有独立通知状态，未改业务生命周期。

准确率改动不增加外部调用。20 个长候选的低预算 fixture 中，旧等长前缀丢失块尾完整条件，新窗口保留审批条件和否定；20 个候选仍在同一预算内，模型输入 26371 字节、预留回答 2048 tokens。中英文、路径/配置标识符、无匹配、UTF-8、转义、单字、空白中心与最终来源预算均有回归。窗口函数本地微基准约 18.710µs/片段、2712 B/op，属于新增本地计算成本，不能称为模型提速。500/950 字符边界不再额外生成纯重叠尾块，500 字符从 2 块降为 1 块；仅影响以后摄取，本轮没有重建历史索引。

完整 AI logic 包曾因冻结题集指纹失败：嵌入的 `evaluation_data/*.json` 在 Windows 被检出为 CRLF。已在根 `.gitattributes` 固定 LF，4 份嵌入副本与对外题集逐字 SHA256 一致；题目、预期指纹及 Git 中 JSON 内容均未改变。修复后原失败回归及 logic 包通过。
